Input rules & scheduling policy

Pure Round Robin ignores priority and memory for scheduling; these fields describe each process. Inputs are limited to 100 processes, 50 CPU bursts per process, and 1,000,000 seconds per value, with millisecond precision. A safety budget of 200,000 events prevents excessive memory use; increase the quantum for larger workloads. I/O operations run concurrently, with no shared-device contention.

At a shared timestamp: arrivals (input order), I/O completions (process order), then quantum expiry/requeue. A CPU burst that finishes at expiry blocks or terminates instead of requeuing. The next job is reserved before switch overhead begins. Switch cost applies only to a direct transition between different processes; initial dispatch and dispatch after idle cost zero. Ready waiting includes dispatch overhead. Registers are an educational model, not actual machine instructions.

THE CONTEXT SWITCH

Pause the work.
Preserve the state.

The PCB preserves the process’s execution context. The dispatcher saves the outgoing PC and registers, selects the next ready process, and restores its context. I/O-bound jobs release the CPU while they wait; CPU-bound jobs use longer CPU bursts.

Here, 1 simulated CPU second advances 100 illustrative instructions. PC advances by 4 bytes per instruction; R0 counts instructions, R1 is a deterministic accumulator, SP stays at the process’s stack base, and FLAGS reflects whether R0 is zero. This makes continuity visible across turns.

Run the built-in regression tests, including the original schedule, I/O wakeups, fractional overhead, simultaneous arrivals, large bursts and register continuity.

Workload classification uses total declared CPU vs I/O time; it is illustrative, not OS utilization profiling.

Turnaround = completion − arrival. Ready wait excludes CPU execution and I/O blocking, but includes dispatch overhead. Response = first CPU start − arrival. Utilization below measures useful CPU execution / elapsed time.
